# 阶段合同、决策记录与三层知识

Codex 负责创意、选择与编排；Node.js 负责参数、版本、状态、预算及执行门禁。此层不增加网络调研、供应商、模型调用、审批弹窗或独立编排器。

## 五类流程

`drama_select_production_workflow` 接受 `drama`、`advertising`、`explainer`、`music-video`、`motion`。每类包含七个阶段，每阶段返回明确的输入名称、必交报告/清单、建议工具、验收项和恢复规则；具体实现见 `src/production-stages.mjs`。建议工具不是一组要全部执行的调用，也不代表当前环境均已具备依赖或授权。

总控按阶段生成真实的 Markdown/JSON 报告或清单，引用已有的素材、任务和版本。可选操作如白模、额外生成镜头可以省略，但需在对应报告中说明；不为了补齐阶段而产生无用素材。

| MCP 工具 | 作用 |
| --- | --- |
| `drama_get_production_progress` | 按项目、创作页、制作类型查询；重验文件哈希，给出第一个未完成阶段及恢复说明 |
| `drama_record_stage_checkpoint` | 追加当前计划版本的产物、验收观察、恢复说明和费用快照；可记录完整或阻塞状态 |
| `drama_record_production_decision` | 追加备选方案、选择及放弃理由、成本影响；更正通过 `supersedes` 保留旧记录 |
| `drama_read_production_knowledge` | 列出三层索引，或读取指定技术/制作参考及其 SHA-256 |

检查点与决策保存在项目状态的 `stageCheckpoints`、`productionDecisions`，由既有原子状态锁保护。按创作页隔离；旧的 `project-legacy` 主创作页与项目级状态共享范围。

同一范围内重复 `requestKey` 且内容一致时返回原记录，内容不同则报冲突。计划版本不匹配会拒绝写入。检查点上游变化或文件被改写时，下游证据不再算当前有效；重新核验并登记即可，不自动删除或重新生成素材。

**这些不是新的审批记录。** 验收观察标记为 Agent 自报；检查点哈希验证只证明报告字节，不能证明已观看媒体。原有图片入库、记忆批准、模型调用和最终交付工具仍是各自边界。阶段完成不能伪装为用户验收或最终交付。

## 决策与成本

记录有意义的创意、供应商、参考、剪辑、恢复和费用取舍；无需记录每个微小操作。未选方案必须说明放弃原因。可只有一个真实方案，不强迫编造备选。

成本影响区分未知、预估增减、无额外供应商调用。仅预估填写金额和币种，必须记录依据；这不会修改费率、费用账本或调用预算。费用快照保留已有账本的分币种估算、账单与未知项，不能相加冒充实付。日志不自动成为已批准的生产记忆。

## 三层知识

- 能力层：MCP、工具能力目录与阶段合同，描述可执行能力和参数限制。
- 制作层：总控、阶段指导与专业 Skill，描述创作方法及验收要求。
- 技术层：工具的 `knowledgeRefs` 指向已有模型接口、本地剪辑及超分资料，按需读取，不复制整套手册。

实现和测试均不要求外部网络调研；参考文件存在不等于供应商账号实测通过。当前适配器与用户目标优先于文档示例。
