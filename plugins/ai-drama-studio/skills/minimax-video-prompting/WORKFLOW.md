# 视频模型提示词：完整制作工作流

> 来源：MiniMax Design 本机 Skill。以下内容已迁移到 OpenDramaFlow 语义。若原工作流与本页顶部的运行时合同冲突，以运行时合同为准。

## 运行时合同

- 项目事实来自 `drama_get_state`，正式剧本/角色/镜头写入使用 `drama_update_plan`。
- 图片由 Codex Image Gen 任务闭环生成；视频由 Seedance 2.5 付费审批链生成；确定性媒体处理使用本地 FFmpeg。
- MiniMax H3 相关模型描述只作为旧提示词迁移背景，不能作为当前供应商参数或能力声明。
- 未接入的供应商、画布节点 API、音色克隆、TTS、音乐生成、3D 编辑器或剪辑工程写入必须显式停止，不得用占位结果冒充成功。

# Video Prompting — AI 视频与图像提示词专家

把创作意图、参考图或提示词草稿整理为清晰的生成简报，并适配所选模型的可见能力和提示词习惯。

## 工作流程

### 步骤 1：确认交付目标

判断用户需要：

- 文生视频提示词；
- 基于已选参考图的图生视频提示词；
- 图像生成或图片编辑提示词；
- 使用 `references/workflows/character-sheets.md` 的角色设定流程；
- 优化已有提示词；
- 在确认提示词后直接生成。

模式不明确时，询问已选图片是否必须控制结果。除非用户要求重新制作，不要替换用户选定的参考图。

### 步骤 2：确认创作约束

确认发布场景或画面形态、片段时长、声音需求、主体身份、必要动作、运镜方式、视觉风格，以及必须保持不变的内容。

把画面形态、片段时长和清晰度写成交付要求，不写成请求字段。生成前根据当前可用能力确认所选模型能否满足；不能满足时，说明可见差异并让用户选择替代方案。

### 步骤 3：选择模型并读取指南

用户指定的模型能够满足要求时优先遵循。否则根据创作需求和当前可用性推荐模型，并阅读对应指南：

| 模型系列 | 适合场景 | 指南 |
|---|---|---|
| Hilo | 通用电影感运动和首帧动画 | `references/models/official-hilo/prompting.md` |
| Kling | 人物表演和可控运镜 | `references/models/kling/prompting.md` |
| Veo | 对对白、环境声和声音设计要求较高的场景 | `references/models/veo3/prompting.md` |
| Wan | 首帧动画、音频驱动表演和简洁运动提示词 | `references/models/wan/prompting.md` |
| 图像模型系列 | 首帧、角色参考、图片编辑、文字呈现或风格化图像 | `references/models/image-models/prompting.md` |

模型名称只表达创作偏好，不代表调用协议。执行前重新确认当前能力，不依赖复制下来的模型菜单。

### 步骤 4：编写提示词

按照以下通用顺序组织，并结合所选指南调整：

```text
[主体与身份] + [动作推进] + [环境] +
[光线与氛围] + [运镜] + [风格] + [需要时的声音意图]
```

遵循以下原则：

1. 使用可看见的具体信息，不堆叠抽象赞美词。
2. 按开始、发展、结束描述动作，复杂度要适合确认的片段时长。
3. 使用一个主要运镜思路，不叠加相互冲突的运动。
4. 参考图控制主体时，明确身份和保留约束。
5. 优先描述想看到的状态；只有所选模型适合时才补充排除项。
6. 需要可靠文字排版时，将文字制作与视频生成分开。
7. 使用用户要求的语言；只有模型指南或用户偏好需要时才强制使用英文。

### 步骤 5：生成前确认

向用户展示：

1. 一份可复制的提示词；
2. 对动作、运镜、风格和声音选择的简短说明；
3. 已选参考图；
4. 已确认的画面形态和片段时长。

先请用户确认或调整创作简报，再进入生成。批量任务先确认统一的人物和风格规则，再展示每个镜头的差异。

### 步骤 6：按需生成

图生视频必须使用用户确认的参考图作为起始画面。需要先制作首帧时，应先展示首帧，获得确认后再生成运动。

所选模型不可用或无法满足已确认要求时：

1. 说明限制；
2. 提出具备同等可见能力的模型；
3. 重新阅读新模型指南，并按其创作规律改写提示词；
4. 结果可能明显变化时先请用户确认。

切换模型时不要保留 provider 专属语法，应保留已确认的主体、动作、构图、声音意图和交付约束。

### 步骤 7：验收结果

按照已确认简报检查主体身份、动作推进、运镜、连续性、画面形态、声音意图、视觉瑕疵和意外文字。如实说明不匹配之处，并提出下一次尝试所需的最小提示词调整。

## 常见失败模式

- 提示词或参考图尚未确认就开始生成。
- 忽略用户选定的图片，另行制作替代图。
- 太晚确认画面形态，导致构图方向变化。
- 在提示习惯不同的模型之间原样复用提示词。
- 声音、身份或运动效果可能变化时静默切换模型。
- 把实现字段或内部模型标识写进提示词。
