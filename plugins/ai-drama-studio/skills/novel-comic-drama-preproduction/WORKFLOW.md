# 小说漫剧前期制片：完整制作工作流

> 本工作流由 OpenDramaFlow 总控调度，默认按 Seedance 2.5 当前适配器执行，但在用户批准开拍前不调用视频模型。

## 运行时合同

- 总控优先：必须完整阅读[总控执行规则](../ai-drama-producer/references/execution-contract.md)。默认 automatic，在用户目标与冻结上限内自动规划、自检和执行；专业阶段的方案/提示词确认不另设人工关卡，除非用户要求或当前为 manual。只要求提示词时不得启动生成。
- 图片：必须先阅读[图片生成与用户验收入库合同](../ai-drama-producer/references/image-asset-contract.md)。默认 Codex 内置图片工具（image2）生成库外候选，展示并经用户验收后才入库／完成任务；仅内置不可用、失败或用户明确要求时使用项目图片模型。自动执行不等于图片验收，也不等于批准生产记忆。
- 视频：Seedance 2.5 使用 `drama_request_paid_batch` 冻结请求，再用 `drama_authorize_and_start_paid_batch` 按当前策略启动；`drama_resume_paid_batch` 只恢复原有 waiting 任务。automatic 不弹产品审批框，manual 才要求可信确认，宿主权限独立。
- 提示词：必须阅读[Seedance 专业指南](../ai-drama-producer/references/seedance-prompting.md)，用当前能力与 ShotSpec 编译请求。参数由当前适配器校验，不继承其他供应商字段或强制节点流程。
- 声音：ASR 与标准音色 TTS 已接入，先查 `drama_get_capabilities`；没有语音 Key 时使用 Seedance 原生声音并实际听音检查。声音克隆、独立音乐生成、3D 编辑器与剪辑软件工程写入尚未接入，不伪造结果。
- 项目与资产：用 `drama_get_state` 读取事实、`drama_update_plan` 保存实际方案；稳定 assetId 与版本不随文件夹路径变化，本地路径不能直接充当供应商 URL。
- 完成：FFmpeg 用于确定性剪辑；生成/下载/探针成功不是交付。按总控检查实际画面、运动、对白、音轨与字幕，记录质量审核后才完成交付。

## 目标与停止边界

把一个已授权小说范围整理为“可以由用户决定是否开始视频生产”的完整前期包。流程可自动连续完成低成本分析、文本整理和本地核验；图片结果必须由用户验收，创作性文本按用户设定的审批方式执行，视频启动始终是单独关卡。

不得把以下状态说成完成：已读原文、已有剧本草稿、图片已生成但未验收、Prompt 已写但素材未绑定、文件已导入但正文仍是待确认、技术核验通过但用户尚未批准开拍。

## 第 0 阶段：建档与授权边界

1. 确认用户拥有或已获得原作使用与改编权限；记录声明，不自行调查或扩大授权范围。
2. 锁定原文文件、版本、哈希、章节索引和本次改编范围。
3. 建立“大项目 → 卷／世界 → 分集创作页”的层级。长篇与无限流作品以卷或世界作为稳定制作单元，分集创作页作为视频交付单元。
4. 确认平台、画幅、语言、目标单集时长、画风、受众与不可改动项。缺少会改变改编结果的选择时只问必要问题。

通过条件见 [阶段与关卡](./references/phase-gates.md)。

## 第 1 阶段：原著证据与连续性账本

1. 阅读本卷全部原文，建立章节、场次、人物、地点、道具、异兽、规则、时间线、伤势和人物关系索引。
2. 对外貌、对白、能力、因果与世界规则保存可定位的原文证据。
3. 将内容分为：明确事实、原文留白、原文内部差异、改编补充。不得把推断写成事实。
4. 外部资料只能解释名词或提供视觉参考，不能覆盖本项目原文。

改编前必须阅读 [原著忠实规则](./references/source-fidelity-rules.md)。

## 第 2 阶段：分卷、分集与时长规划

1. 按剧情目标、冲突升级、场景转换与悬念落点确定集数，不按章节数量机械等分。
2. 建立每集对应章节、核心事件、开场钩子、高潮、结尾钩子与预计时长。
3. 依据对白量、动作复杂度、场景数量和镜头节奏估算时长；发现目标时长无法容纳原著内容时，调整集数或取得删改授权。
4. 核验本卷所有章节均有去向，允许一个章节跨集或多章合并，但必须保存映射。

## 第 3 阶段：完整文学剧本

1. 逐集编写完整场次剧本，包含场次、时空、人物、动作、表演、对白、旁白、因果和转场目的。
2. 人物原话优先使用原文；为画面节奏补充动作和环境细节时，不改变人物立场、事件结果或世界规则。
3. 每个场次标注来源章节与改编类型；原创桥接不得伪装成原文。
4. 对照原著完成首轮覆盖审计，再进入资产生产。

格式要求见 [文学剧本与镜头规范](./references/screenplay-and-shot-spec.md)。

## 第 4 阶段：资产需求与视觉圣经

1. 从完整剧本反推角色、状态、服装、表情、场景、道具、异兽、特效与声音资产。
2. 区分系列公共资产、卷／世界资产和单集专用资产；优先复用已批准版本。
3. 为每项视觉资产建立原文证据、创作目的、版本、参考职责、需要的视图和验收标准。
4. 先锁定画风、主角身份锚点和高复用场景，再制作长尾资产。
5. 三视图、五视图或表情板按下游一致性需要决定，不把设定板数量当成固定仪式。

## 第 5 阶段：图片候选与用户验收

1. 生图前读取已批准人物母版、画风和原著证据；同类资产分批处理。
2. 所有新图先存项目素材库之外，记录提示词、参考版本、真实路径和哈希。
3. 实际查看身份、体态、构图、瑕疵、文字、裁切与风格一致性，再以“候选、尚未入库”展示给用户。
4. 只有用户明确采用的具体候选才能入库；退回或未决定图片继续留在本地。
5. 修改图片产生新候选和新哈希，必须重新展示，不能覆盖旧批准版本。

完整规则见 [图片审批规则](./references/image-approval-policy.md)。

## 第 6 阶段：导演分镜、Prompt 与声音意图

1. 先产出每集导演分镜总览，再产出逐镜生产表。
2. 每镜必须包含镜头编号、预计时长、景别、机位、运镜、主体位置、动作起止、表演、对白／旁白、声音、字幕、转场、连续性、素材职责和验收标准。
3. 静态画面描述与动态视频描述分离；Prompt 不重复堆叠抽象风格词，写成可观察、可执行、可检查的镜头合同。
4. 引用图片时记录稳定资产身份和批准版本，不能用“同名最新图”替代冻结版本。
5. 单镜时长和生成模式必须符合当前真实能力；超长叙事拆成连续镜头，不虚构模型能力。

格式要求见 [文学剧本与镜头规范](./references/screenplay-and-shot-spec.md)。

## 第 7 阶段：全卷原著与生产审计

按批次完成后统一检查：

- 章节是否全部覆盖，关键事件、人物原话和因果是否保留；
- 人物年龄、体态、服装、伤势、能力和关系是否跨集一致；
- 异兽、道具和世界规则是否被名称联想或网络资料带偏；
- 每个镜头是否可在给定时长内完成动作与对白；
- 素材缺口、未批准候选、重复哈希、旧状态文字和失效引用是否为零；
- 声音、字幕和转场是否与剧本和镜头一一对应。

发现问题时只修正受影响范围，重新运行相关审计；不得为了通过检查删除原著内容。

## 第 8 阶段：正式项目资产准入

1. 项目资产只接收已明确、已批准、版本与范围清楚、可直接复用的文件。
2. 原文快照、机械索引和可验证摘录可在校验后归档；剧本、视觉设计、导演分镜和 Prompt 等创作性文本必须有审批状态。
3. 候选、草稿、预检、临时拼图、测试稿、废稿、未采纳和被替代版本不进入项目资产。
4. 文件夹名称不能代替正文状态；入库前检查名称、正文、哈希和审批证据。
5. 已批准资产修改时建立新版本，不静默覆盖；清理只移除项目资产副本，不删除用户的本地制作记录。

完整规则见 [项目资产准入规则](./references/asset-admission-policy.md)。

## 第 9 阶段：开拍前冻结与交接

1. 生成符合 [前期制片清单数据结构](./references/preproduction-manifest-schema.md) 的卷级清单。
2. 运行来源覆盖、项目资产和开拍就绪三类核验；错误为零后才可声明“等待开拍批准”。
3. 冻结原文版本、分集方案、剧本、镜头、资产版本、声音方案、画幅、生成参数范围、调用上限和验收标准。
4. 向用户展示缺口为零的就绪摘要，并等待明确的“开始视频制作”指令。
5. 用户批准后，把冻结清单交给总制片流程；本 Skill 到此结束，不自行启动视频调用。

## 批量策略

- 先完成整卷原著拆解，再完成全部分集结构。
- 先完成全卷文学剧本，再反推资产清单。
- 图片按角色、场景、道具和异兽分批生成与审批，不按单镜头交替生成。
- 先完成各集导演总览，再批量编译逐镜 Prompt。
- 最后统一做原著审计、资产清洗和开拍前冻结。

## 失败与恢复

- 原文缺章或版本变化：停止受影响卷，更新来源索引并重新计算覆盖范围。
- 原著存在冲突：登记差异并让用户选择采用依据，不擅自抹平。
- 图片退回：保留已批准母版和旧引用，只为被退回项创建新候选。
- 剧本或分镜被修改：仅失效受影响的下游 Prompt、素材需求和审批证据。
- 本地文件与项目资产不一致：以稳定资产身份、版本、哈希和审批记录核验，不按文件名猜测。
- 核验脚本失败：保留报告和真实错误，不把部分通过说成全卷就绪。

## 完成输出

必须同时交付：来源与章节索引、分集结构、已批准文学剧本、资产清单、已批准视觉资产、导演分镜总览、逐镜 Prompt、声音与字幕方案、审批证据、项目资产审计报告和开拍前就绪清单。

最终状态只能是以下之一：

- `needs-work`：仍有来源、审批或素材缺口；
- `ready-for-video-approval`：前期包完整，等待用户批准开拍；
- `approved-to-start-video`：用户已明确批准，可交给总制片启动视频生产。
