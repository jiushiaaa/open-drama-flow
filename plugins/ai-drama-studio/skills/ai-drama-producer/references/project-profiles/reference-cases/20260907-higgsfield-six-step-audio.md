# Higgsfield六步制作流程：本项目迁移与Seed Audio实测

日期：2026-09-07。适用 project-mtl3tme8-a115bdff。用户要求学习官网六步经验并检查现有豆包语音Key能否使用Seed Audio 1.0。本次是方法沉淀和一次独立接口验证，不是重拍第一章或批量制作第二章。

- [Seed团队模型介绍](https://seed.bytedance.com/en/blog/from-speech-to-audio-creation-introducing-the-seed-audio-1-0-audio-creation-model)：模型将语音、音效与环境等组织成场景声音；能力说明不是本项目效果验收。

官方经验与从业者经验都保留；来源标签与本项目验证标签独立。平台营销中的无缝一致性、成本或自动同步说法不作为质量保证，也不套用到当前工具。

## 六步对应我们的制作交接

| 步骤／官网工具 | 官网核心方法简述 | 本项目具体执行与交接 |
| --- | --- | --- |
| 1 剧本与场次 | 先分场，再列镜头和角色地点 | 从原著提取本场事实、原台词、动作与观察对象；输出镜头表及在场/入画/画外名单。先发现重复人物、眼线和起坐问题，再生成。镜头数按戏剧节奏，不照搬示例数量。 |
| 2 Soul ID | 给重复出场角色建立持久身份 | 使用已认可脸型/发型/肤色基准、服装及状态版本，每镜显式绑定。现有参考资产不等于训练过Soul ID；不为模仿其参考数量批量重生图片。需要新角度才补充，并与身份基准核对。 |
| 3 Popcorn | 将同一场作为连续分镜序列规划 | 先看全场关键节拍的构图与动作关系，确保门、沙发、电视、人物位置统一。只做当前场必要分镜；格数不限，也不把多宫格直接当单镜输入。单镜参考应清楚分工，避免复制多人。 |
| 4 Cinema Studio | 以分镜及明确摄影设定生成镜头 | 固定场内主光方向、色板和风格；按镜头目的明确景别、焦距意图、运动及变化原因，避免自动曝光/白平衡导致换肤色。参数是否真的可控以适配器为准，不发明镜头API字段；先试当前场最难但有代表性的片段，再展开。 |
| 5 Seed Audio | 按场组织对白和环境等声音 | 在分镜时就列声音事件与入点，不到剪完才考虑。保留认可角色声音；按需比较原生音画或独立音频，不把成功接口当作稳定配角音色。声音主导节奏时先审音频再驱动画面；画面已锁时不擅改台词时长或母版。 |
| 6 Supercomputer | 保存镜头顺序、组织生成与组片 | 用本地项目状态、资产版本和剪辑清单保存交接；只有输入无相互依赖的镜头才可在已授权范围并行。依赖上一镜实际末帧的链不能盲目并行。合片检查入口、片内和出口的动作/声音/字幕，保留逐段来源及SHA256。 |

### 最值得落实的三项改变

1. **难镜头先验证**：多人互动、手与道具接触、复杂状态变化先用一个代表镜头试出可行调度；不意味着先把整章最激烈情节批量生成。
2. **先整场规划，再按镜头生产**：统一空间和摄影逻辑，不等于全场一口气生成，也不意味着提前翻新全库。时长服务完整动作单元；文章对长镜头的经验不是所有模型的硬限制。
3. **声音是设计输入**：对白、停顿、环境、关键音效进入同一场次表。首尾帧/续写有助交接但不保证自然，时间戳有助字幕但不保证口型；返回结果仍需正速看与听。

四条手绘三渲二规则、第一章认可基线和用户分段审片约定不变。没有为本项目训练Soul ID、安装Higgsfield或验证Popcorn；这些平台工具不能写成已调用。

## Seed Audio 1.0：现有Key的实际验证

**结论：现有豆包语音Key在本次官方国内接口调用中成功生成音频。无需因本次需求更换Key。**

- 官方端点：`POST https://openspeech.bytedance.com/api/v3/tts/create`；`X-Api-Key`，请求体 `model: seed-audio-1.0`。不同于当前标准TTS的 `seed-tts-2.0` SSE接口；也不是Ark视频Key或Higgsfield账户凭据。
- Key只由现有本地DPAPI保管模块读取并发往固定官方域名，不写入脚本、日志、聊天、文档或新平台。
- 范围：一次请求，无重试；提示词要求约6秒安静室内测试，一句普通话与轻微脚步；无角色参考上传、无声音克隆、未绑定任何生产镜头。
- 返回HTTP 200，实际音频6秒，计费时长字段6秒；金额未查询，不承诺免费。
- 请求与服务日志标识仅保留在本地诊断记录，不随公开方法论发布。
- 音频SHA256：`847d3b56aa878041f61b243f2620d3b8b416a90c7e5409e5a2d8f049c8712908`。
- 输出和诊断凭据位于 `本地私有证据目录（由制作清单解析，不随仓库发布）`，分别为 `seed-audio-20260907-test.wav` 与 `seed-audio-20260907-probe.json`。只含脱敏请求和结果，不含Key。
- 已返回逐字时间戳，测试句区间0.400–2.880秒。不能将供应商字幕当作独立ASR或实际听审证据；声音表演、脚步和环境效果仍需试听。

### 接入与下一次验证边界

现有制作适配器仍只管理ASR和标准TTS。本次是独立最小诊断，不代表正式增加了Seed Audio任务类型、角色音色绑定、字幕同步或失败恢复功能。不能把新模型名直接塞进旧SSE请求。

官方接口支持自然语言时长/时间线意图、参考输入和字幕返回；提示词要求6秒不构成硬时长参数保证。若后续用户要求正式接入，应单独实现请求冻结、单次额度、固定域名、超时不盲重试、结果持久化与试听门禁，再以短场景验证：台词无增删、多角色不串音、环境不压对白、时间点可用、跨段音色保持。不要用本次一句话成功推断上述均已通过。

正式制作默认继续现有认可声音路线；本测试不替换第一章音轨。未来授权的独立声音试片在用户认可前保持候选状态。
