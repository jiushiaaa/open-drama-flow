# 图片生成与用户验收入库合同

适用于所有创作 Skill 的图片素材，包括角色母版、表情板、场景、产品图、分镜图和修改后的新版本。此合同优先于迁移资料中“目检后回填”“自动登记产物”等旧表述。

## 默认路线

`已授权的图片需求 → Codex 会话内置图片工具 → 候选暂存 → 在会话展示 → 用户验收 → 写回项目素材库 → 绑定下游引用`

- 默认使用当前 Codex 会话提供的内置图片生成工具（用户称为 image2）。按当前工具注册表调用实际可用的图片工具；不要把 image2 当成方舟模型 ID，也不要虚构工具不支持的模型参数。
- Codex 内置图片工具不是项目自带的 Seedream API。已配置方舟 Key、项目旧设置选过 Seedream、拥有全模型权限、自动执行模式，都不是切换图片供应商的理由。
- 仅当用户明确指定项目图片模型，或已核实内置工具不可用／执行失败时，才考虑项目自带图片模型。记录工具不可用或失败的真实证据、切换原因和新调用的范围；不静默切换、不无限重试。超时但结果未知时，先找回原调用结果，不能直接换模型重生成。权限拒绝和安全限制不可通过换供应商绕过。
- 项目图片模型也必须遵守“候选暂存、用户验收、再入库”。如果某个现有接口会在生成后直接导入项目，不能用它生产尚未验收的候选；改用支持独立输出路径的生成方式，否则说明这一接口边界，不把入库当作暂存。

## 生成授权与结果验收是两件事

1. 遵守本次创作的调用次数、参考图与生成授权。项目 `automatic` 只免除范围内每次调用的产品弹窗，不代表用户看过或接受了结果；用户另设的生成前设计审核仍然有效。
2. 先读取已批准的角色／产品母版与相关原作，确认参考图及版本。不要把未批准的记忆候选当成已锁定设定。纯图片创作不需要为了调用内置图片工具虚构视频时长、MP4 brief 或分镜任务。
3. 生成结果保留在工具输出目录或项目素材库以外的本地候选暂存目录。记录真实路径、SHA-256、提示词、参考图版本、工具与本次调用证据；不要提前调用 `drama_import_asset`、`drama_complete_image_task`，也不要把候选登记到项目 `assets` 或“候选与废案”素材文件夹。
4. 实际查看候选图，检查身份、构图、瑕疵、文字和裁切。把图显示在当前 Codex 会话，明确标注“候选，待你验收，尚未入库”。Agent 的目检通过不等于用户验收。
5. 等待用户对已展示的具体候选明确确认，例如“这张通过，入库”或“采用第 2 张”。批准提示词、同意开始生成、沉默、全访问权限或不明确的“继续”不能替代结果验收。多张图必须辨明批准的那几张。
6. 入库前重新核对批准候选的路径、哈希与目标项目；图片字节或创意内容改变后须重新展示验收。只导入通过的版本，保留已有母版与旧引用。记录候选版本／哈希、用户验收依据和新 `assetId`／版本的对应关系，不伪造人类审批来源。
7. 未批准、被退回或尚需修改的图留在库外；不得设为角色母版、生产记忆或 Seedance 参考。用户提出修改时生成新的候选并再次验收，而不是覆盖已批准版本。

## 与 Harness 的衔接

- **已有合法图片任务：**领取一次任务，按冻结提示词与预算生成并展示候选。等待用户验收期间，不完成任务、不续跑消费该图片的视频。用户批准后才调用 `drama_complete_image_task`，在检查记录中注明验收依据；该工具会登记项目资产，不能当作候选上传接口。跨轮恢复先核对候选和原任务，避免重复付费。
- **独立图片素材任务：**直接使用 Codex 内置图片工具完成候选生成，无需为了领取任务先启动整条视频链。用户批准后用 `drama_import_asset` 导入指定文件夹，保存生成与验收记录，再按需关联创作页。不得声称未运行的 Harness 批次已经成功。
- **下游生产：**只引用已入库并验收的精确 `assetId` 和版本。自动执行模式不会跳过本合同的用户图片验收，也不会激活未批准的生产记忆。

本合同是 Codex 的操作约束，不把现有导入 API 的技术成功误称为服务器独立验证了用户同意。用户手动上传已有文件仍按其上传意图办理；不要以本规则清理或移动已有资产。
