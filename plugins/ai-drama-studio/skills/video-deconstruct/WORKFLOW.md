# 视频拆解与复刻：完整制作工作流

> 本工作流由 OpenDramaFlow 总控调度，默认按 Seedance 2.5 当前适配器执行。

## 运行时合同

- 总控优先：必须完整阅读[总控执行规则](../ai-drama-producer/references/execution-contract.md)。默认 automatic，在用户目标与冻结上限内自动规划、自检和执行；专业阶段的方案/提示词确认不另设人工关卡，除非用户要求或当前为 manual。只要求提示词时不得启动生成。
- 图片：必须先阅读[图片生成与用户验收入库合同](../ai-drama-producer/references/image-asset-contract.md)。默认 Codex 内置图片工具（image2）生成库外候选，展示并经用户验收后才入库／完成任务；仅内置不可用、失败或用户明确要求时使用项目图片模型。自动执行不等于图片验收，也不等于批准生产记忆。
- 视频：Seedance 2.5 使用 `drama_request_paid_batch` 冻结请求，再用 `drama_authorize_and_start_paid_batch` 按当前策略启动；`drama_resume_paid_batch` 只恢复原有 waiting 任务。automatic 不弹产品审批框，manual 才要求可信确认，宿主权限独立。
- 提示词：必须阅读[Seedance 专业指南](../ai-drama-producer/references/seedance-prompting.md)，用当前能力与 ShotSpec 编译请求。参数由当前适配器校验，不继承其他供应商字段或强制节点流程。
- 声音：ASR 与标准音色 TTS 已接入，先查 `drama_get_capabilities`；没有语音 Key 时使用 Seedance 原生声音并实际听音检查。声音克隆、独立音乐生成、3D 编辑器与剪辑软件工程写入尚未接入，不伪造结果。
- 项目与资产：用 `drama_get_state` 读取事实、`drama_update_plan` 保存实际方案；稳定 assetId 与版本不随文件夹路径变化，本地路径不能直接充当供应商 URL。
- 完成：FFmpeg 用于确定性剪辑；生成/下载/探针成功不是交付。按总控检查实际画面、运动、对白、音轨与字幕，记录质量审核后才完成交付。

# 视频拆解与复刻

以证据为先：先读视频和关键帧，再写结论与复刻合同。不要把“分析”当作直接生成的替代品，也不要把截图推测说成已读取的视频事实。

## 输入与证据链

1. 用户上传视频时，先用 `本地媒体核验（view_image、ffprobe 或 FFmpeg）` 读取元信息和语义；记录时长、画幅、分辨率、主体、场景、动作、镜头、光影、节奏和可听声音。
2. 语义分析失败、过粗，或用户要求精细复刻时，用 `本地 FFmpeg` 建立高密度关键帧拼图：15 秒内至少 10–12 帧；更长视频按可读的连续片段分拼图；快动作、转场密集时提高到约每秒一帧。拼图容量不得小于实际抽帧数。
3. 将关键帧拼图写入画布；完整 Markdown 报告也写入画布，并用 `sourceNodeIds` 关联关键帧。只有截图或文字描述时，明确标注哪些动作、声音或时序仅为推测。
4. 仅给 URL 时，不承诺下载外部视频；请用户上传视频、关键帧或足够的文字描述。

## 拆解报告

用户未指定重点时，默认深拆角色/主体、剧情/动作、镜头/运镜、光影/风格与节奏；已指定时不重复问。报告包含：

1. 元信息、分析依据与一句话定性；
2. 关键帧数量、拼图数量和覆盖时间；
3. 角色与视觉锚点、场景、动作时间线、镜头、光影色彩、风格材质、剪辑节奏、声音；
4. 可复刻事实、不可确定项和风险（人脸、手部、多人身份、文字、快速运动或风格漂移）；
5. Seedance 2.5 复刻计划、统一约束和自检结论。

为每个主体保留同一名称与可见识别点；用可观察证据描述景别、机位、运镜、光源、材质和动作，不用“电影感”“高级”等空词代替分析。

## 编译视频复刻合同

先调用 `drama_get_capabilities`，确认当前选定视频模型的 mode、时长、画幅、分辨率、音频和 refs 能力。用户未指定模型时默认选择当前 Seedance 适配器；用户锁定其它模型时，按该模型的能力卡编译，不静默换回 Seedance 2.5。

1. 按连续性分组，而不是按固定 15 秒切段。主体、场景、动作流、声音意图和 refs 兼容时尽量组成最长可行 clip group；跨场景、主体/风格硬切、首尾帧依赖或运行时能力限制时才拆分。
2. 为每组写清起始状态、连续动作和可承接的末态。下一组从上一组的可见末态或明确切换开始，不能只以“保持一致”代替事实。
3. 当前模型为 Seedance 2.5 时，按其 运行时能力合同 生成最终 Prompt：`全局基准 → 每个参考素材的角色 → 环境光影 → 空间基准 →（有对白时）角色声音签名 → 画面演进 → 声音设计 → 画面风格`。逐镜头按顺序写景别、机位/观察方向、一个主运镜、主体行为、重要背景反馈、对白或同步声音与末态；其它模型只使用其对应能力卡的合同。
4. 使用用户给定的素材和画布中的有效证据。每个 `@图片N`、`@视频N`、`@音频N` 都逐项说明锁定的身份、场景、风格、动作或声音；保持用户附件顺序。普通参考图不是首尾帧，只有用户明确指定时才按首帧、尾帧或关键帧处理。
5. 模型的自动优化只能补足未指定内容：不得删改主体、动作、空间关系、构图、镜头顺序、声音或否定要求；用户要求静音、无对白、无音乐或仅保留指定声音时严格保留。精确 UI、文字或图形要求必须逐字锁定，不以“禁止文字/Logo”一律删除。
6. 当前模型为 Seedance 2.5 且写实人物清晰可见时，写自然哑光肤质、正常肤色、真实细节和镜头实际需要的光线；多人镜头先用全景建立关系，再用不同信息量的中近景/近景承接互动，避免脸部混合与重复面孔。
7. 读取总控 Seedance 专业指南；多参考输入还需读取 [多参考绑定](references/seedance-multi-ref.md)。

## 交付与执行

1. 默认在画布交付“视频拆解报告”和“视频复刻计划”两个文档节点。复刻计划列出每个 clip group 的时长/画幅/模型锁、refs、Prompt、起止状态和风险点。
2. 用户只要分析或提示词时，停在可编辑复刻计划，不调用生成；用户明确要求生成时，按确认的模型锁和有序 refs 调用 `Seedance 冻结请求与策略授权执行链（见总控执行规则）`。
3. 完成后检查：关键帧证据已上画布；每个结论有证据或推测标记；最终 Prompt 符合当前模型的完整合同，且具备逐镜头动作/声音；refs 与素材顺序一一对应；不存在遗留模板变量、无依据新增剧情或被丢失的用户限制。

## 边界

- 不把固定“每 15 秒一条时间戳 Prompt”作为通用规则，也不向非 Seedance 模型输出其专用模板。
- 不因拆解任务自动生成字幕、可读 Logo 或水印；但用户明确要求的精确文字/UI 要保留并采用确定性叠加路径。
- 只做普通剪辑、字幕、压缩、转码或影评时不触发本 Skill。
